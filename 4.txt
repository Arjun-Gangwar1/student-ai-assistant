Below is a complete structured explanation of the project so you can directly convert it into resume project description + interview explanation.

1️⃣ What is Parsec Singularity Framework

Parsec Singularity is an AI-powered productivity assistant framework designed to automatically understand and organize a student's digital life using data from platforms like Gmail, Google Classroom, and Calendar.

Instead of manually checking emails, assignments, deadlines, and documents, the system:

• Extracts information from emails
• Understands attachments (PDFs, images)
• Identifies tasks and deadlines
• Creates reminders
• Summarizes important information

Core Idea

Build a central AI brain that processes all incoming academic information and turns it into structured tasks and insights.

Think of it like:

Gmail + Calendar + Classroom + AI Assistant → One intelligent dashboard

2️⃣ Main Problem It Solves

Students receive information across multiple platforms:

• Emails
• Classroom announcements
• Attachments (PDF schedules, notices)
• Registration deadlines
• Event updates

Important information often gets lost inside long emails.

Singularity solves this by

✔ Automatically analyzing emails
✔ Extracting important data
✔ Creating structured knowledge
✔ Helping users query information via AI

Example queries:

What assignments are due this week?
Summarize today's important emails
Show registration deadlines

3. Proposed Solution (Phase-1)
3.1 Overview

In the first phase of the Smart AI Assistant for Students, we implement a real-time, AI-driven academic assistant that integrates Gmail, Google Classroom, and an AI reasoning engine (GPT / Ollama) using Pathway’s streaming architecture.
The goal of this phase is to demonstrate how scattered academic information can be automatically understood, prioritized, and converted into actionable insights for students, without requiring manual monitoring.

Unlike traditional rule-based notification systems, our solution continuously processes incoming data streams, understands their academic context, and proactively assists students by generating alerts, summaries, and calendar actions.

3.2 Phase-1 Objectives

The Phase-1 implementation focuses on the following core objectives:

Real-time ingestion of Gmail and Google Classroom data
Intelligent classification of academic emails and classroom updates
Automatic extraction of deadlines, assignments, and important events
AI-based prioritization and decision making
Proactive student notifications and reminders

This phase serves as a working prototype for the larger long-term vision of a fully autonomous student AI assistant.

3.3 System Architecture (Phase-1)

The Phase-1 system follows a streaming-first pipeline, where data flows continuously through multiple intelligence layers.

1. Data Sources

The system monitors two primary academic data sources:

Gmail: Administrative emails, faculty communications, and academic notices
Google Classroom: Assignments, due dates, and course updates

These sources represent the most critical information channels used by students on a daily basis.

2. Ingestion Layer (Pathway Connectors)

Incoming data is ingested using Pathway’s real-time connectors, which operate in a streaming mode:

Gmail API Connector
Google Classroom API Connector

Pathway automatically detects new emails or classroom updates and streams them into the system without batch reprocessing or manual triggers.

3. Streaming Intelligence Layer

This layer forms the core processing unit of the system and operates continuously on incoming streams.

It performs the following tasks:

Mail Classification: Identifies whether an email is academic, administrative, event-related, or irrelevant
Deadline Extraction: Detects due dates, submission times, and exam schedules
Assignment Detection: Recognizes classroom assignments and required tasks
Priority Scoring: Assigns importance levels based on urgency and relevance
Light Overload Detection: Flags situations where multiple deadlines or tasks overlap

This ensures that only meaningful and time-critical information progresses further in the pipeline.

4. AI Reasoning Engine

An AI reasoning layer powered by GPT or Ollama is used to perform higher-level decision making.

The AI engine:

Interprets extracted information in natural language
Determines the importance of each event or task
Selects appropriate actions, such as notifying the student or scheduling a reminder

By combining streaming data with AI reasoning, the system avoids notification spam and focuses on actionable intelligence.

5. Action & Output Layer

Based on AI decisions, the system generates two types of outputs:

Google Calendar Actions
Automatic event creation
Deadline reminders
Student Alerts
Real-time notifications
Concise summaries of important updates

These outputs ensure that students receive the right information at the right time, without manual tracking.

3.4 Key Contributions of Phase-1

The Phase-1 solution demonstrates:

Real-time academic data understanding
AI-based prioritization instead of rule-based alerts
Seamless integration of Gmail, Classroom, and Calendar workflows
A scalable foundation for future predictive and personalized features
3.5 Phase-1 Impact

By implementing this architecture, the system reduces students’ cognitive load and helps prevent missed deadlines and overlooked communications.
Phase-1 establishes a strong technical and conceptual foundation for extending the assistant toward predictive risk analysis, workload optimization, and fully autonomous academic planning in future phases.

1. Context

A modern college student interacts daily with multiple digital platforms such as official email, academic portals, document repositories, and messaging applications. These platforms continuously generate large volumes of unstructured and semi-structured data including announcements, PDFs, schedules, assignments, and messages.

At IIT Dharwad, critical information such as mess menus, bus schedules, academic deadlines, events, and administrative notices are primarily communicated through emails and portals. This information is time-sensitive, frequently updated, and highly personalized based on the student’s year, branch, and interests.

2. Problem Statement

Despite the availability of information, students face significant challenges:

Important emails and PDFs are buried among irrelevant messages
Deadlines for assignments, registrations, and events are missed
Students must manually search emails and portals for basic queries
Messaging platforms are noisy, causing urgent information to be overlooked

The core issue is information overload, not information scarcity.

Traditional batch-based systems and static dashboards fail to address this problem because they:

Operate on outdated data
Lack personalization
Do not act proactively

Student life operates in continuous time:

Mess menus change daily
Transport schedules update unexpectedly
Event deadlines expire quickly
